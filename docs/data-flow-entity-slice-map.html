Phrase to entity

New Entity Swimlane

A selected phrase becomes an entity whose first rule is the regex for that phrase. (Everlink, the earlier one-motion story-to-lore flow, was retired on 2026-10-27; see docs/everlink-it-concept.md.)

1. Select a phraseIn any document. The bubble offers New entity, or the entity whose rule already matches the whole selection.
2. Name itThe selection, whitespace collapsed, becomes the entity name.
3. Derive the rulepatternFromText escapes the phrase, allows any whitespace between words and either apostrophe, and adds word edges.
4. Create atomicallycreateEntity writes the entity and its rules in one transaction; invalid patterns never pass the IPC schema.
5. Highlight liveThe editor compiles the rule once and highlights every visible match. No match is stored.

Renderer actionSelection to name plus starting rule.useEntityActions.ts
Pattern rulesEscape, word edges, compile, validate.shared/matchingPatterns.ts
Trust boundaryRefuses patterns that don't compile.shared/contracts/harnessSchemas.ts
Database transactionEntity plus rules, one event each.WorkspaceRepository.ts, EntityRepository.ts

Passage to entity

Add Slice Swimlane

Bind a selected passage in the current document to an entity (FB-002, once called Everslice).

1. Select passageThe non-empty main editor selection is frozen when the chooser opens.
2. Pick entityThe chooser filters entities by name, rule and slice text; the author picks one or names a new one.
3. Optional createA new entity is created first, with the regex for its name.
4. Same-doc anchorFrozen selection positions bind against the active document's editor snapshot.
5. Create slicecreateSlice writes Slice, SliceBoundary and EntitySlice and appends sliceCreated.
Reading it back: hover any highlight to see the entity's slices; clicking one opens its document and selects it.

Edit survival

Document Edit And Boundary Repair Flow

Every prose edit can move anchors forward without letting stale ranges silently point at wrong lore.

1. Prose transactionProseMirror emits steps and inverse steps from an editor transaction.
2. Append historyDocument steps and optional checkpoint are written before projection update.
3. Update projectionDocument currentVersion, contentJson, plainText, and metrics move forward.
4. Remap boundariesMapping moves SliceBoundary TextAnchors through the same step set.
5. Surface resultresolved/repaired/ambiguous/invalid controls preview and repair UX; lost slices can be placed again in Edit slices.
ResolutionMeaningRequired behavior
resolvedMapping preserved the range confidently.Preview and decoration can render normally.
repairedExact text plus context recovered the range.Render with visible confidence if needed.
ambiguousSeveral plausible ranges exist.Fail closed; never pick one silently.
invalidRange collapsed, deleted, or cannot be found.Surface repair state; do not preview wrong content. Positions are never mapped again (ADR-009).
